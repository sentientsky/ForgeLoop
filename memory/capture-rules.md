# Capture Rules

Capture is how ForgeLoop compounds.

The Capture stage should create durable memory without creating paperwork for its own sake.

## Capture When

Capture when a task includes:

- a decision
- a reusable fix
- a repeated mistake
- a new project preference
- a review finding that should not repeat
- a changed fact
- a useful pattern
- a workaround

## Do Not Capture When

Do not create a full capture note for:

- tiny typo fixes
- throwaway experiments
- temporary local commands
- information that would expose secrets

For tiny work, a short final note is enough.

## Exact Wording

Preserve exact wording when it matters, especially for:

- user preferences
- final decisions
- bug explanations
- important constraints
- acceptance criteria

Summarise only after the source has been preserved.

## Promotion Rules

If a lesson repeats:

- once: create a capture note
- twice: create or update a solution note
- three times: promote it to a skill, template, reviewer, hook, or standard

## Safety Rules

- Never store secrets.
- Redact sensitive data.
- Mark outdated memory as superseded.
- Link related memory.
- Keep notes short enough to reuse.
